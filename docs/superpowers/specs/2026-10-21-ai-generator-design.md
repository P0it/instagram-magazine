# AI 생성기 설계

2026-10-21. 레퍼런스·템플릿을 보고 "이걸로 만들어 줘" 하면 **완성 수준의 캐러셀 초안**을 만들어 주는 기능. 이 문서는 해당 범위에서 `docs/01-system-design.md`의 "AI 호출" 항목을 확장한다. 단, 아래 "예외 요청"에 적은 두 가지는 CLAUDE.md의 절대 규칙과 부딪히므로 구현 전에 규칙 문구를 함께 고친다.

## 의도

사용자는 레퍼런스(잘 되는 피드)와 템플릿을 계속 모은다. 매번 슬라이드를 처음부터 짜는 대신, 레퍼런스를 골라 "어떤 내용으로 쓸 거다"라고 지침만 주면 AI가 그 레퍼런스의 구성·톤·디자인을 닮은 캐러셀 한 세트를 만들어 해당 계정의 `draft` 포스트로 떨어뜨린다. 사용자는 마지막에 텍스트 내용과 위치를 조금 손본다. 즉 초안이 아니라 **거의 완성본**이 목표다.

## 목표 / 비목표 / 안티 목표

**목표**
- 레퍼런스·템플릿 상세에서 "AI로 생성하기" → 지침(글) + 선택 이미지 첨부(없어도 됨) → 비동기 작업 → 계정의 `draft` 포스트.
- 설정에서 Claude / ChatGPT **구독 계정 OAuth 로그인**. API 키 없이 구독 플랜으로 호출.
- Instagram 규격과 디자인 규칙을 **데이터로 된 규약**(spec)으로 정의하고, AI 프롬프트와 서버 검증이 같은 규약을 쓴다.
- 결과는 한 번에 보여 준다. 진행 상태만 보인다(스트리밍 아님).

**비목표**
- 생성 중 슬라이드가 한 장씩 채워지는 실시간 미리보기.
- 이미지 생성(AI가 사진을 그리는 것). 사진은 첨부, 스톡, 기존 업로드로만 쓴다.
- 자동 게시. 생성물은 항상 `draft`.
- 여러 사용자, 권한 분리.

**안티 목표 (기술적으로 돌아가도 실패)**
- 텍스트가 영역을 넘치거나 겹치거나 1080 규격을 벗어난 슬라이드가 통과하는 것.
- 토큰이 브라우저, 로그, Drive로 새는 것.
- 로그인이 풀렸는데 작업이 조용히 실패하고 사용자는 이유를 모르는 것.

## 예외 요청 (CLAUDE.md 절대 규칙과의 충돌)

1. **"Google Drive 자격증명은 환경변수에만"** 규칙은 Google 한정으로 읽는다. AI 로그인 토큰은 같은 정신으로 **`.env.local`에만** 둔다(Drive·DB 금지). 로컬 Node 프로세스가 `.env.local`에 쓰고 읽는 방식은 `src/lib/google/local-env.ts`가 이미 한다. 구현 시 CLAUDE.md의 해당 문장에 "AI 제공자 토큰 포함"을 추가한다.
2. **"스크린샷 분석은 ANTHROPIC_API_KEY → 없으면 `claude -p` 순"** 규칙은 새 `AiProvider` 계층으로 대체한다. 우선순위: 로그인된 OAuth 제공자 → (있으면) API 키 → `claude -p`. 기존 `layout-analyst.ts`, 레퍼런스 분석은 단계적으로 이 계층으로 옮긴다(이번 범위에서는 신규 기능만 새 계층을 쓰고 기존은 건드리지 않는다. 마이그레이션은 별도).

## 확정한 결정 (사용자)

- **구독 OAuth 로그인**을 쓴다. CLI 위임(`claude -p`)이 아니라 앱이 직접 OAuth를 처리하고 토큰을 받아 호출한다. Claude와 ChatGPT를 **처음부터 둘 다** 지원한다.
- 결과물 단위는 **완성된 캐러셀 한 세트**(여러 장 + 캡션 + 해시태그).
- 앱은 로컬에서 돌고 상태는 Drive에 있다. 맥을 바꿔도 이어서 쓰지만 AI 로그인은 다시 한다.
- 진행은 **비동기 작업 큐**. 결과는 완료 후 한 번에.
- 결과는 "콘텐츠 만들기"(`/home`) 보드에 해당 계정의 `draft`로 나타난다.
- 역할 에이전트: **카피라이터**, **레퍼런스 분석가**, **콘텐츠 딜리버리 검수자**를 생성 흐름 안에서 차례로 호출한다(사용자가 "카피라이터와 콘텐츠 딜리버리 전문가가 필요하다"고 했다. 레퍼런스 분석가는 기존 큐레이터·마케터·UI/UX 분석을 쓰는 것으로 내가 정리한 것).
- 구독 로그인 약관 리스크는 사용자가 인지하고 수용했다. 구현은 한 모듈에 격리해 방식이 바뀌어도 교체 가능하게 한다.
- **구현의 첫 단계는 가능성 확인(스파이크)이다.** 제공자별로 OAuth 로그인 → 실제 호출 1회 → 이미지 입력 가능 여부를 확인한다. 한 제공자라도 OAuth 토큰이 제3자 클라이언트로 거부되면 **그 제공자만 CLI 방식(`claude -p`, Codex CLI)으로 대신 연결**하고, 된 제공자는 OAuth를 유지한다(사용자 결정). 두 방식 모두 같은 `AiProvider` 인터페이스 뒤에 둔다. 설정 화면은 제공자마다 어떤 방식으로 연결됐는지(OAuth / CLI) 보여 준다.

## 구성

### 1. AI 제공자 계층 — `src/lib/ai/provider/*` (server-only)

```ts
interface AiProvider {
  id: "claude" | "chatgpt";
  status(): Promise<{ loggedIn: boolean; account?: string; expiresAt?: string }>;
  complete(req: { system: string; user: string; images?: { mime: string; bytes: Uint8Array }[]; schema: z.ZodType; signal?: AbortSignal }): Promise<unknown>;
}
```

- 호출 결과는 항상 Zod 스키마로 검증하고, `any` 금지.
- 토큰 만료 전 자동 갱신(refresh). 갱신된 refresh token이 바뀌면 `.env.local`에 다시 쓴다.
- 429·5xx는 지수 백오프 재시도(`GoogleDriveClient`의 재시도와 같은 방식). 구독 한도 초과는 재시도하지 않고 "한도 초과, 몇 시에 다시"를 사용자에게 알린다.
- 둘 다 로그인돼 있으면 설정에서 고른 기본 제공자를 쓴다. 한쪽만이면 그쪽.

### 2. OAuth 로그인 — `src/app/api/ai/oauth/[provider]/{start,callback}`

- PKCE 인가 코드 흐름. 로컬 서버가 콜백을 받는다.
- Claude(Claude Code 방식)와 ChatGPT(Codex CLI 방식)의 **엔드포인트·클라이언트 id·스코프·콜백 주소는 구현 시작 전에 해당 CLI의 동작을 조사해서 확정**한다. 이 문서는 값을 정하지 않는다. 일부 제공자는 `localhost` 고정 포트 콜백만 허용할 수 있어, 그 경우 설정 화면이 안내한다.
- 토큰은 `.env.local`(`AI_CLAUDE_*`, `AI_CHATGPT_*`)에만 저장한다. 브라우저에는 `provider / loggedIn / account / expires_at`만 내려간다.
- 설정 > "AI" 섹션: 제공자별 로그인·로그아웃(토큰 삭제), 상태, 기본 제공자 선택, 마지막 오류.

### 3. 규약 — `src/presets/spec/*.json` + `src/lib/ai/spec.ts`

데이터 파일로 둔다(레이아웃 프리셋이 JSON인 것과 같은 방식).
- **게시 규격:** 비율별 캔버스(`FORMAT_INFO` 재사용), 캐러셀 장수 범위, 이미지 형식·용량, 캡션 글자 수 한도, 해시태그 개수 한도, 프로필 그리드 안전 영역.
- **디자인 규칙:** 글자 크기 하한·상한, 텍스트 영역 한도, 장당 텍스트 분량 상한, 허용 폰트, 레이어 종류별 허용 값, 표지·본문·마무리 역할 규칙(`SlideRole`).
- 수치의 근거(Instagram 공식 규격 등)는 값마다 `source`를 달고, 조사 결과로 채운다. 수치는 이 문서가 아니라 규약 파일이 진실이다.
- 같은 규약을 두 군데서 쓴다: (a) 프롬프트에 삽입, (b) 생성 결과 검증기(`validateAgainstSpec`).

### 4. 생성 파이프라인 — `src/lib/ai/generate/*`

입력: `account_key`, `reference_id?` 또는 `template_id?`, `brief`(지침 글), `attachments?`(이미지, Drive 임시 폴더), `format?`(기본 4:5), `slide_count?`.

단계:
1. **분석(레퍼런스 분석가):** 레퍼런스의 기존 `insight`(큐레이터·마케터·UI/UX)가 있으면 재사용하고, 없으면 먼저 분석한다. 가까운 템플릿·룩·색 조합 후보를 고른다.
2. **카피(카피라이터):** 지침과 레퍼런스의 구성·톤을 받아 표지 후크, 장별 문구, 캡션, 해시태그를 쓴다. 계정의 기존 포스트 톤을 참고 자료로 줄 수 있다(분량이 크면 최근 몇 건만).
3. **레이아웃:** 장별로 기존 `LAYOUT_PRESETS`·템플릿·룩·색 조합 중에서 **고르게** 한다. AI가 좌표를 새로 그리는 것은 허용하지 않고, 프리셋 id와 `overrides`(스키마가 허용하는 값)만 낸다. 결과는 `SlideDef`로 변환한다.
4. **딜리버리 검수:** `validateAgainstSpec`가 텍스트 넘침(렌더 기준 높이 추정), 글자 크기 하한, 안전 영역, 장수, 캡션·해시태그 한도를 점검한다. 위반 항목을 모아 AI에게 **최대 2회** 수정 요청한다. 그래도 위반이면 완료하되 `warnings`에 남기고 포스트를 `draft`로 두어 사람이 보게 한다(생성 전체를 실패시키지 않는다).
5. **저장:** 기존 포스트 저장 경로(`src/lib/metadata`)로 `draft` 포스트를 만든다. `metadata`에 생성 근거를 남긴다: `generation: { reference_id?, template_id?, brief, provider, spec_version, generated_at }`. `PostMetadataSchema`에 선택 필드로 추가하고 `schema_version`은 올리지 않는다(optional 추가).

역할 프롬프트는 `src/lib/ai/roles/{copywriter,analyst,delivery}.ts`에 둔다. 각 역할은 시스템 프롬프트, 입출력 Zod 스키마, 단위 테스트 가능한 순수 조립 함수를 가진다. 기존 `ref-*` 에이전트 정의는 이 레포에 없고 외부에서 돌고 있으므로 직접 의존하지 않는다.

### 5. 비동기 작업 큐 — `src/lib/ai/jobs/*`, `_system/ai-jobs.json`

- 작업 스키마(`src/types/ai-job.ts`, Zod): `id`, `status`(`queued|running|done|failed|canceled`), `stage`(`analyze|copy|layout|review|save`), 입력 요약, `post_id?`(완료 시), `error?`(`{stage, message, kind}`), `created_at`, `updated_at`.
- 저장은 Drive JSON. 기존 `writeSystemJson`의 버전 충돌 처리를 쓴다. DB·KV·Blob 금지.
- 실행은 로컬 서버 프로세스 안에서 **한 번에 하나씩** 순서대로(구독 한도 보호). 서버 시작 시 `running`으로 남은 작업은 `failed(interrupted)`로 정리하고 사용자가 "다시 시도"할 수 있게 한다.
- API: `POST /api/ai/jobs`, `GET /api/ai/jobs`, `GET /api/ai/jobs/[id]`, `POST /api/ai/jobs/[id]/cancel`, `POST /api/ai/jobs/[id]/retry`. 클라이언트는 TanStack Query 폴링(기존 `src/lib/client/queries.ts` 방식).
- 크론은 쓰지 않는다. 생성은 사용자가 직접 요청한 것만 실행한다("자동 게시 금지" 규칙과 무관하게도 자동 생성은 하지 않는다).

### 6. 화면

- 레퍼런스 상세, 템플릿 상세에 "AI로 생성하기" 버튼 → 모달: 계정 선택, 규격(기본 4:5), 장수(기본 자동), 지침 텍스트, 이미지 첨부(선택).
- 로그인 안 돼 있으면 모달 대신 설정 > AI로 안내.
- 사이드바 근처에 작업 진행 표시(진행 중 개수, 현재 단계), 클릭하면 작업 목록(상태, 실패 이유, 다시 시도, 완료된 건의 포스트 링크).
- 완료되면 `/home` 보드의 해당 계정에 `draft`로 나타나고, 카드에 "AI 생성" 표시.
- 화면 배치·모양은 구현 계획 단계에서 목업으로 별도 확인한다. 이 문서는 정보 구조만 정한다.

## 제약 / 지켜야 할 규칙

- DB 없음. 상태는 Drive JSON과 `.env.local`뿐.
- AI·Drive·토큰 코드는 `server-only`. 클라이언트에는 `provider/loggedIn/account/expires_at`만.
- 모든 Drive JSON과 모델 응답은 Zod 스키마로만 읽고 쓴다. `any` 금지.
- 캔버스 폭 1080 고정, 높이는 포스트 규격.
- 게시는 사용자의 `/api/posts/[id]/publish` 호출로만.
- Next.js 16 관례(요청 API `await`, `proxy.ts`). 작성 전에 `node_modules/next/dist/docs/`의 관련 문서를 읽는다.
- Mock 모드(`npm run dev` 기본)에서도 전체 흐름을 돌릴 수 있게 `MockAiProvider`를 둔다. 고정 응답으로 큐, 검증, 저장, 화면을 테스트할 수 있어야 한다.

## 테스트

- 단위(vitest): 규약 검증기(넘침·하한·장수 위반 케이스), 프롬프트 조립, 응답 스키마 파싱(깨진 JSON, 잘린 응답), 토큰 갱신, 큐 상태 전이, 중단된 작업 정리.
- 통합: `MockAiProvider`로 작업 생성 → 완료 → `draft` 포스트 생성 확인, 검수 위반 시 재요청 후 `warnings` 기록.
- e2e(playwright): 설정 로그인 상태 표시(Mock), 상세에서 생성 → 진행 표시 → 보드에 초안.
- OAuth 실제 로그인은 자동 테스트하지 않는다. 수동 확인 절차를 구현 계획에 적는다.

## 검토에서 정한 것 (내 판단 — 사용자가 확인할 것)

- **이미지 입력:** 구독 OAuth 경로가 이미지를 받지 못하면, 분석 단계는 이미 저장된 `insight`와 `palette`(텍스트)만으로 진행하고 첨부 이미지는 슬라이드 사진으로만 쓴다. 제공자별로 `supportsImages`를 `AiProvider`에 노출하고 화면에서 "이 제공자는 이미지를 읽지 못해요"를 알린다.
- **넘침 검증:** 캔버스 렌더는 브라우저(next/font 자체 호스팅 폰트)에서만 이뤄지고 서버에는 글자 폭 측정 수단이 없다. 첫 버전은 서버에서 글자 종류(한글·영문·숫자)별 폭 비율로 줄 수를 **보수적으로 추정**하는 함수로 한다(애매하면 위반으로 본다). 정확한 측정(폰트 파일 + 서버 측 측정 라이브러리)이 필요한지는 구현 중 오탐 정도를 보고 구현자가 정한다. 에이전트가 새 레이어를 만들 수는 없고, 프리셋·템플릿이 정한 텍스트 자리에 문구를 채우고 허용된 `overrides`만 바꾼다.
- **작업 큐 재시작:** 앱은 한 번에 한 인스턴스만 돈다고 가정한다. 작업 레코드에 `owner`(인스턴스 id)와 `heartbeat_at`을 두고, `running`인데 heartbeat가 일정 시간(구현자가 정함, 처음엔 2분) 넘게 멈췄으면 `failed(interrupted)`로 본다. 서버 시작 훅에 기대지 않고 목록을 읽을 때와 러너가 일을 잡을 때 정리한다.
- **첨부 이미지:** 작업마다 Drive 임시 폴더에 두고, 슬라이드에 실제로 쓴 이미지만 포스트 폴더로 복사한다. 임시 폴더는 작업이 끝나면(성공·실패·취소) 지운다.
- **토큰 저장:** 메모리 캐시가 1차 출처이고 `.env.local`은 재시작을 위한 보관용이다. 쓰기는 단일 쓰기 잠금 안에서만 하고, refresh token이 바뀌면 쓰기가 성공한 뒤에 캐시를 바꾼다. 쓰기가 실패하면 설정 화면에 "다시 로그인 필요할 수 있음"을 표시한다. `next dev`가 `.env.local` 변경으로 다시 뜨는 것은 허용한다(작업은 interrupted 처리).
- **기본 제공자·마지막 오류:** 이 맥의 로컬 상태이므로 `.env.local`(`AI_DEFAULT_PROVIDER`)과 메모리에 둔다. Drive에 두지 않는다(맥마다 로그인이 다르기 때문).
- **호출 예산:** 한 작업의 AI 호출은 최대 6회(분석 0~1, 카피 1, 레이아웃 1, 수정 최대 2, 여유 1)로 제한한다. 카피와 레이아웃은 한 호출로 합칠 수 있으면 합친다. 한도를 넘으면 현재 결과로 `warnings`를 달아 완료한다.

## 구현자에게 남기는 것

- 각 제공자 OAuth의 구체 값(조사 후 확정), 수치 규약의 세부 값, 프롬프트 문구, 단계별 모델 선택(비용과 속도 균형), 폴링 간격, 화면 세부 모양.
- 작업 큐를 모듈 레벨 단일 러너로 둘지 Next 서버 수명주기에 맞춰 시작할지는 구현자가 `next dev`/`next start` 동작을 확인해 정한다.

## 나중에 (이번 범위 아님)

- 기존 레퍼런스 분석·스크린샷 분석을 `AiProvider`로 이전.
- 생성 결과에 대한 "다시 만들기(같은 조건)" 버튼, 부분 재생성(한 장만).
- 승인된 포스트의 성과를 보고 규약을 갱신하는 피드백 루프.
